# 本地 AI 日志怎样进入记忆

适用于用户已选择的 Claude Code、Codex、Gemini CLI、OpenCode、Cursor 本地日志。原始字节完整保留，Markdown 保存正文，PostgreSQL 保存任务、证据属性与检索索引。不扩大采集范围，不沿日志中的路径读取额外文件。

## 原始记录与可用证据分开

先按来源格式解析事件，再交给模型提取记忆，不把任意 JSON 递归拼成用户发言。

| 原始内容 | 处理方式 |
| --- | --- |
| 真实用户消息、明确的用户选项回答 | 用户陈述，可提取目标、约束和决定 |
| 助手的可见答复 | 助手报告，保留“未独立验证”的归属 |
| Codex guardian / approval reviewer 会话 | 根据原生来源在读取正文前排除，原日志不变，不生成 Source 或记忆 |
| Codex 子代理、Claude sidechain 的任务输入 | 父代理委派背景，不归属为用户发言，也不能作为主证据；实际报告和结果仍可提取 |
| 工具返回、后台任务通知 | 工具观察，保留错误、返回、未配对等状态 |
| 工具调用、助手进度提示 | 理解上下文，不能作为完成事实的主证据 |
| 自动压缩摘要、历史重放、系统配置、推理内容、队列遥测 | 仅存原始审计，不重新生成事件 |
| 不认识的内部格式 | 仅存审计，不猜测说话人或发生过的事 |

工具的读取分类只作为证据属性，不再据此丢弃返回；模型结合用户目标判断实际配置、故障原因和关键约束是否值得记忆，也可忽略目录列表等无关结果。成功的轮询和任务状态回执仍排除。Edit/Write 的文件正文、diff 和全部工具调用体仅留审计；正文只保留必要的工具名/文件路径与短结果。支持识别 SSH 内的读取、`cd … && ls`、管道和轮询。每轮工具证据最多 8 条，单条结果约 220 字符，优先保留错误与关键结果；助手可见发言最多 3 条，每条最多约 1600 字符。工作目录每轮只出现一次。用户原话与选项回答不按工具预算裁剪。工具结果中的引用、代码和读入资料不等于用户经历。

可识别的 Git 子命令按出现顺序附在发起调用的轮次末尾，采用独立行范围。调用记录提供原始记录 ID、原生调用 ID 和可用的会话工作目录。参数及完整命令保存在原始审计。同轮返回列出对应的原始记录；跨轮返回保留在实际收到的轮次，可在同一会话与分支内按调用 ID 对照。复合命令共用整次调用的返回，调用记录仅作为上下文。支持直接 shell 调用和 Codex 字面量 exec_command 包装；动态脚本留在原始审计。

信息取舍、轮内归并、证据选择与是否生成记忆由 MLLM 判断；来源角色、引用有效性、轮次边界与预算仍由程序约束。纯会话配置、无有效事件的片段直接跳过，只推进采集游标。大轮次的原件审计分块保存在 metadata，不创建占位 Markdown；有正文的有效轮次正常生成 Source。

识别原生事件重复，以及 Codex 同一工作片段内的 `event_msg`/`response_item` 镜像消息。不做跨项目的文本相似度删除；不同时间的相同表达可能是新的确认或修正。来源实例、原生对象 ID 和原始字节哈希共同确定幂等键。投影版本改变不再创建独立任务身份；更高 generation 会替换旧投影，旧版重放不能降级当前投影。不同文件是否为同一会话仍取决于原生身份，不能只凭相似文字推断。

Gemini 的 `$set`/`$rewindTo` 属于上下文替换，不重新导入整段活跃历史；`$patch` 只呈现更改的消息部分。OpenCode 的消息片段通过父消息确定角色。Cursor 只接受已识别的显式消息结构，未识别的内部状态保留审计。

## 分块保留工作上下文，证据保留事件边界

按会话、分支、真正的用户轮次组成工作片段，跨采集页保留未结束轮次。自动摘要和后台通知不会伪造新用户轮次；每个真正用户轮次最多一个最终 Unit（可为零）。达到约 512 Ki 字符或 200 条原始记录时，将已收集原件写成仅审计分块，接续有界语义材料和原件哈希链；轮次结束才提交一次语义提取。单条原始记录仍服从读取器上限，不能把原始记录切断。采集分页和进程恢复不改变最终轮次身份。Claude 的两种 AskUserQuestion 回答前缀以及 Codex 的显式问答均按用户选择处理。

用户消息与选项回答使用独立预算：每条最多约 24000 字符，超长时保留首尾并明确标注节选，完整原话仍在审计分块中。父代理委派背景最多约 4000 字符。工具调用体、文件内容和 diff 不进入跨块语义接续材料；调用身份和分类仍保留，供后续结果配对。

Codex 单条原始记录默认上限为 16 MiB，以容纳一次工具返回多张图片的情况，显式配置的来源上限优先。类型化工具输出只把文字块作为文本观察，图片编码保留在原始审计；HTTP 和模型输入预算不随之增大。

工具输出中的 NUL 字符在正文入口显示为 `\u0000`，原始字节仍保留在审计中；行号不变。PostgreSQL 索引也对遗留正文做同样的文本投影，避免一个不可索引字符阻塞整批写入。后台先同步待修复索引，再处理新写入；共享索引故障由后台等待恢复，不逐条消耗模型并使无关任务失败。

模型批次容纳多条精确观察，每条带独立定位符、角色、时间和证据属性。长观察可继续分片，已处理内容通过有界工作记忆传递。模型只提取新增的目标、关键选择、变更、验证结果、失败原因和未决事项；没有持久价值的片段可以不生成记忆。

本地工作日志的覆盖账本直接根据输出引用计算，不要求模型重复填写输入/输出编号。调用只作为上下文、结果作为事实时，前者可以不产生独立记忆。普通材料仍保留原来的逐项覆盖校验。

## 归属与时间是写入约束

模型为每条摘要和 Unit 选择当前批次的精确 `anchor`。程序验证并将它并入引用依据，直接根据原始角色确定 `claim`；归属与时间不再要求模型猜测。调用、进度提示和旧上下文不能作为新事实的主证据。

Unit 正文固定带“用户表示”“助手报告（未独立验证）”或“工具结果记录”的前缀。模型仍负责判断文字是否被证据支持；角色校验不等于对自然语言完成真实性证明。创建脚本不等于执行成功，启动任务不等于任务结束。

AskUserQuestion 的模型材料将逐字回答与助手的问题背景分开；问题前提与助手转述不能当作用户确认。用户说“大幅扩充”不等于同意助手自行补充的“10k、3 epochs”等配置。归并后的正文仍须分别说明用户要求与助手提案。

时间由主证据的原始事件时间确定，不接受模型填写；缺失就保持 unknown，不能借用会话开始时间。转述的历史日期写入正文，不冒充本次观察的发生时间。证据属性单独存入 PostgreSQL，在摘要到 Unit、重启恢复之间保持。

## 修复与检索边界

仅审计材料、等待激活的新投影与已被替代的旧 Source 不进入普通检索。原件按内容哈希单份保存在 `.meta/source-originals/`，通过 metadata 引用；被撤下的旧正文与派生记忆清空，控制状态只留小型替换回执。替换旧投影须撤下由旧证据生成的 Unit/detail，阻断相关旧视图，再使用原始记录重新排队。原日志可重导且用户明确要求不备份时，直接清理导入数据，不创建额外副本。不能只改提示词却留下已经污染的记忆。会话顺序在 PostgreSQL 中物化，直接维护“延续”关系及其删除、替换后的前后衔接，不逐条请求关系模型。

可重复执行的维护入口：停止 core 和 acquisition 后，运行 `python ops/reproject_import.py JOB_ID` 查看范围，再加 `--apply`。脚本先同时备份记忆目录、采集状态与 PostgreSQL，保存可恢复计划，持久接收新投影，再清理该已选来源的旧代数据与孤立 metadata。它不调用模型；恢复服务后由正常写入队列处理。选择范围保持不变。

不备份而从原日志重建：停止服务后运行 `python ops/restart_local_ai_imports.py` 查看范围，再加 `--apply`。它只允许仓库完全属于已暂停的本地 AI 导入时清理，遇到其他写入或任务会拒绝。保留来源配置、原始日志、原有批次及选择范围，删除旧正文、索引、写入记录与采集游标，再恢复服务。稳定定位符计数器不会归零。


归一化元数据保留原始记录数、有效事件数、重复及导航过滤数量；日志不打印材料。使用小型合成故障验证角色、时间、跨页和恢复，不为日常修复反复运行完整真实模型链路。
