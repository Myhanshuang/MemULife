# 外部模型直接修订记忆

本协议允许用户授权的外部模型利用完整会话上下文，通过 `memory_write` 提交最终改稿。核心服务只校验并提交，不再调用内部模型改写这份改稿。原有素材导入继续使用默认 `mode=ingest`。

本协议的实现与后续演进须遵守[核心设计原则](core-design-principles.md)，尤其是稳定引用、统一事务、手动内容保护和后台一致性约束。

## 修订协议

先用 `memory_read` 读取目标及新增引用，复制返回的 `edit_revision`。随后提交：

```json
{
  "from": "当前认证身份",
  "mode": "revise",
  "idempotency_key": "一次逻辑修改的唯一标识",
  "reason": "用户说明实验 A 和实验 B 属于同一研究主题",
  "changes": [{
    "ref": "u12:3",
    "expected_revision": "读取返回的 edit_revision",
    "old_text": "原样摘录的待修改内容",
    "new_text": "实验 A 是视频时序理解研究中的一次尝试。",
    "add_refs": ["c42:10-18"],
    "add_relations": [{"rel": "相关", "target": "u27:8"}],
    "add_topics": ["视频时序理解"]
  }]
}
```

- `old_text` 不必是全文，但必须非空、精确匹配且只出现一次。不做模糊匹配、自动合并或冲突覆盖；不能把正文改成空白。
- 同时检查目标版本。冲突返回当前正文、引用、关系、主题和 `edit_revision`，模型重新阅读后决定是否再提交。
- 单批最多 20 个目标，每个目标最多修改一次；所有目标和引用先校验，再原子提交。任一冲突不提交任何修改。
- `mode=revise` 顶层必须提供非空 `reason`、`idempotency_key` 和 `changes` 数组；目标与替换字段放在数组各项内。缺字段或类型错误返回 `invalid_arguments`，附带 `details`（字段、错误类型、具体原因）和 `trace_id`。MCP 与核心日志通过该编号关联，只记录错误类别，不记录正文、参数或凭据。
- Source、Detail 不接受此模式；日/月 Summary 与 Runtime 按稳定条目 ID 修订。Unit 的原有证据和关系默认保留；`add_refs` 只接收现存 Source/Detail/媒体证据，Unit 间关联使用 `add_relations`。
- 存在性校验不证明引用支持所写结论。外部模型必须实际阅读证据，区分用户陈述与模型推断。修改理由用于溯源，不充当权限凭证。
- `add_topics` 建立显式主题归属；自动分类不能移除这些归属，但删除该 Unit 后不能使它复活。
- 写权限由服务端认证身份决定。MCP 不开放文件路径、SQL、删除、清空或内部 projection 控制元数据；管理页面的所有者维护入口独立保留。

## 稳定行号与版本

Unit ID 继续使用已有定位符，例如 `u12:3`。修订记录采用带格式标识的单行 JSON 存储，正文中的换行编码在 JSON 内；原记录占用的其余物理行留空。记录起始行不变，文件物理行数不变，其他条目的原始字节不变。读取器同时兼容旧格式与修订格式，不迁移或重排已有文件。

日/月 Summary 和 Runtime 新写入的条目也采用该编码，以原样保留换行和分隔符；条目身份由 `entry_id` 决定，不依赖视图文件行号。已有旧格式只在正常写入目标视图时更新。包含新编码的仓库需要新版读取器，不能直接回退到不识别修订格式的旧核心。

每条记录返回结合内容指纹与最新修订编号的 `edit_revision`，独立于同文件其他 Unit 的变化；改回旧正文也不会复用旧版本。数据库显式保存修改前后内容、版本、调用身份、原因、时间和事务编号；事务本身不替代版本历史。`memory_read(history=true, refs=[目标])` 可查询目标修订历史，历史记录的 `body` 为包含 before/after 的 JSON。恢复旧内容通过一次新的修订完成，不删除历史。

同一身份重试相同 `idempotency_key` 和相同参数返回同一回执；换参数复用该键返回冲突。

## Unit 与视图条目保护

日/月 Summary 与 Runtime 入口仍使用 `r5` 等定位符；每个条目另有稳定 `entry_id`。入口读取保留聚合正文，并通过 `view_entries`（Runtime 兼容保留 `runtime_entries`）返回各条目的 ID、引用、版本与 `protected` 状态。用 `memory_read(refs=["r5"], entry_id="…")` 读取某个条目的准确正文；加 `history=true` 可只查询该条目的历史。分页的 `truncated=true` 表示正文尚未完整返回，可提高 `budget_chars`（最大 100 万字符）后读取。

- 修改现有条目：`ref=r5`，同时提供 `entry_id`、该条目的 `expected_revision`、`old_text` 和 `new_text`。外部修订后的条目默认受保护。
- 追加条目（仅 Runtime）：`ref=r5`，不提供 `entry_id`，提供入口的 `edit_revision`、空 `old_text`、非空 `new_text` 和至少一个现存 Unit 引用。程序分配 ID 并保护新条目。
- 受保护条目的正文、引用、ID、主题归属不能被自动汇总改写、删除或合并。自动汇总只更新其余部分；保护在底层视图写入处执行。
- 对受保护内容继续手动修改，必须指定 `allow_protected=true` 并通过版本和原文校验；修改后仍受保护。只有显式 `protect=false` 才解除保护。普通自动更新不能绕过保护。
- 引用被所有者删除后，保护条目保留原文和引用，并标记 `invalid_refs`。失效证据不进入有效引用集合或新的自动汇总依据。

Unit 修改同样默认保护。自动重新导入淘汰旧投影时，保留这些 Unit 及其证据文件；所有者明确执行删除仍可删除，保护不会让已删记录复活。

## 管理页面编辑

Unit、日/月 Summary 卡片与详情提供“编辑”，记忆主题提供“编辑记忆”。编辑器读取完整正文与条目版本，通过同一个 `memory_write(mode=revise)` 提交；多条 Summary/Runtime 可选择具体条目。页面保存始终保护内容，列表显示“已保护”。版本冲突保留草稿并提供最新正文供重新读取；未知网络结果使用原幂等键重试。保存提交后关闭弹窗，索引和汇总异步重建。Source 不提供编辑。

## 提交、索引与后台任务

正文、审计历史、显式主题归属、索引失效标记和汇总任务在同一核心事务中保存。沿用 PostgreSQL 控制表与文件发布日志，失败回滚；已提交但未发布的文件由日志恢复。

提交立即返回 `done`，表示修订已持久提交；检索与汇总状态另行标明。原定位符保持有效，但正文改变后必须更新关键词索引、关系索引和受影响 Unit 的向量。后台重建相关日/月汇总和未保护的 Runtime 部分，禁止重放原始素材生成流程覆盖修订。索引滞后时不把旧索引结果伪装成最新状态；直接读取返回当前正文。

MCP 写入重新启用后，客户端需重新获取工具列表。模型应仅在用户授权整理/修改记忆时使用修订模式；精确目标已确定时不要求用户逐项重复确认。

## 必要验收

验证精确替换、整批回滚、版本冲突、引用类型/存在性、幂等、原文件行数和其他条目字节、Runtime 保护及失效引用、修订后检索更新。使用隔离数据，不在真实记忆中写入测试实验。
