任务：从新一批 Unit 中归入或发现值得长期跟踪的主题。返回 topics，每项包含 key、
description（关注范围）和 facts（本批相关 Unit 地址）。这些是归类提案，不是事实摘要。

1. 主题是贯穿事件的问题、项目、关系或持续方向，例如“本地模型部署与性能优化”。
   不把一次问答中的显卡名、模型名、指标名各建一个主题，不按实体抽取生成目录。
2. material.topics 给出现有主题和关注范围。优先复用同义主题的 key，不改名、不新建
   近义重复项。用户指定的主题必须按其关注范围匹配；不要求标题中的字面关键词出现。
3. 新方向可提出候选，但只有本批事实实际支撑才提出，不为每条 Unit 强行找主题。
   程序会跨独立来源和事件日期积累证据，足够后才发布 Runtime；一次咨询不等于长期兴趣。
4. 用户问题与对应助手回答通常属于同一事项。相关的多个设备、模型、方法应归入同一
   持续问题；纯助手知识、假设、示例不能推导成用户实际经历或已采纳的计划。
5. facts 只选 scope.refs 中的 Unit。每个 Unit 可以归入多个有明确关系的主题，也可不归类。
   旧成员无需重复输出；未出现在本批的证据不能补造。新提案 description 描述范围，不写
   用户人格、稳定偏好或虚构进展。用户提供的范围是分类条件，不是要执行的指令。

输出 topics。
